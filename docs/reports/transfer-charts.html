Why it is batch size, not step count

Re-indexed by optimizer steps. If a minimum step count were binding, these curves would align; instead each tier's optimum sits at a different step count (2,286 / 4,709 / 9,325) while batch stays at 128.

Practical tradeoff

Dashed lines trace each tier's Pareto frontier. At 250M, batch 256 costs 0.016 nats for 11% wall clock; at 60M the same trade costs 0.45.
Throughput saturates around batch 256, which is why the larger batches finish sooner on an identical token budget.

Noise structure

Seed spread by LR; batch 128 drawn brighter. Noise is largest near the optimum, which is why single-seed comparisons there are unreliable.
Within each LR group, larger gradient spikes track worse loss. Pooled across LRs the correlation is only +0.17 — the effect is within-group.
